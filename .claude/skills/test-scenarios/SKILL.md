# test-scenarios

이슈 번호 `$ARGUMENTS`의 완료 체크리스트를 테스트 시나리오로 바꾼다.

인자가 없거나 숫자가 아니면 이슈 번호를 사용자에게 물어보고 멈춘다.

**이 스킬은 코드를 구현하지 않는다.** 함수 본문, 컴포넌트, 테스트 코드는 쓰지 않는다. 단계 2와 4에서는 반드시 사용자 승인을 받은 뒤에 다음 단계로 넘어간다.

## 절차

### 1. 이슈 읽기

```
gh issue view $ARGUMENTS
```

- 이슈 본문과 "완료 체크리스트" 항목을 모두 읽는다. 체크리스트 항목에 `C1`, `C2`처럼 번호를 붙여 이후 단계에서 참조한다.
- `gh`가 없거나 로그인되어 있지 않으면 그 사실을 알리고 멈춘다. 이슈 내용을 추측해서 만들지 않는다.
- 필요하면 `docs/features/tag/spec-fixed.md`와 `src/`의 관련 코드를 읽어 용어와 기존 함수를 확인한다.

### 2. 함수 시그니처 제안 → 승인

체크리스트를 만족시키는 데 필요한 함수마다 아래를 표로 제안한다. 기존 함수(예: `validateTag`)가 있으면 재사용 여부를 먼저 밝힌다.

| 함수명 | 입력 | 출력 | 에러 메시지 |
|---|---|---|---|

- 입력과 출력은 TypeScript 타입으로 쓴다.
- 에러 메시지는 UI에 보이는 한국어 문구를 그대로 적는다. 에러가 없으면 `-`로 둔다.
- 제안 뒤 **승인을 요청하고 멈춘다.** 수정 요청이 있으면 반영해 다시 제안한다. 승인 전에는 3단계로 넘어가지 않는다.

### 3. 테스트 시나리오 제안

승인된 시그니처를 기준으로 시나리오를 `[정상]`, `[경계]`, `[예외]`로 나눠 제안한다.

- 형식은 `함수명 should <기대 결과> when <조건>`이다.
- 시나리오마다 어느 체크리스트 항목(`C1` 등)을 다루는지 표시한다.
- **경계값은 최대-1, 최대, 최대+1을 모두 포함한다.**
  - 최대값이 정의된 입력(길이, 개수 등)에만 적용한다.
  - 최대값이 정의되지 않았으면(예: 태그 길이·개수는 제한 없음) 억지로 만들지 않는다. 대신 0개, 1개, 여러 개 같은 의미 있는 경계를 쓰고, 최대값이 없다는 사실을 한 줄로 밝힌다.
- 예외는 입력 오류와 저장된 데이터가 없거나 깨진 경우를 포함한다.

### 4. 대조표 → 승인

체크리스트 항목이 시나리오에 빠짐없이 들어갔는지 대조표로 보여 준다.

| 체크리스트 | 시나리오 | 구분 |
|---|---|---|

- 시나리오가 하나도 없는 항목이 있으면 표 아래에 눈에 띄게 적고, 시나리오를 추가한 뒤 다시 보여 준다.
- 체크리스트에 없는 시나리오가 있으면 "체크리스트 밖"이라고 표시한다.
- **승인을 요청하고 멈춘다.** 승인 전에는 파일을 저장하지 않는다.

### 5. 저장

승인되면 `docs/features/tag/scenarios-$ARGUMENTS.md`에 저장한다. 이미 있으면 덮어쓰기 전에 사용자에게 알린다.

문서 구성:

1. 제목과 이슈 번호
2. 함수 시그니처 표 (2단계에서 승인된 것)
3. 시나리오 (`[정상]`, `[경계]`, `[예외]`)
4. 대조표 (4단계에서 승인된 것)

저장 후 파일 경로를 알리고, 구현은 하지 않았음을 한 줄로 밝힌다.

## 주의

- 승인 없이 다음 단계로 넘어가지 않는다.
- 시나리오는 체크리스트와 `spec-fixed.md`에 있는 동작만 근거로 삼는다. 없는 규칙을 만들어 내지 않는다.
