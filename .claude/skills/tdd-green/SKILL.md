# tdd-green

`tdd-red`로 만든 실패 테스트를 **한 번에 하나씩** 통과시킨다. TDD의 Green 단계다.

시작 전에 `npx vitest run`을 한 번 돌려 현재 실패 목록과 개수를 확인한다. 실패하는 테스트가 없으면 "남은 실패: 0"이라고 알리고 끝낸다. 실패 원인이 `not implemented`가 아닌 Broken(`Cannot find module` 등)이면 구현하지 말고 사용자에게 알린다(`tdd-red`의 영역이다).

## 규칙

- 한 번에 실패한 테스트 **하나만** 고른다. 여러 개를 한꺼번에 풀지 않는다.
- 그 테스트를 통과시키는 데 필요한 **최소한**만 쓴다.
- **테스트에 없는 기능은 추가하지 않는다.** 미리 일반화하거나 대비 코드를 넣지 않는다. 필요한 동작은 테스트가 요구할 때 구현한다.
- 테스트 파일은 고치지 않는다. 테스트가 틀렸다고 판단되면 고치지 말고 사용자에게 보고한다.
- 이 프로젝트 규칙을 따른다: 컴포넌트는 named export만, 이벤트 함수 이름은 `handle`로 시작, 파일은 200줄 이하, UI 문구는 한국어.

## 반복 절차

### 1. 실패한 테스트 하나 고르기

실패 목록에서 가장 단순한 것(정상 → 경계 → 예외 순)을 하나 골라 어떤 테스트인지 한 줄로 밝힌다.

### 2. 최소 구현

고른 테스트만 통과하는 가장 작은 변경을 한다. 이때 **바꾼 파일과 내용을 기억해 둔다.** 되돌릴 때 필요하다.

### 3. 매번 전체 테스트 실행

`npm test`는 watch 모드라 끝나지 않으므로 전체를 한 번만 도는 명령을 쓴다.

```
npx vitest run
```

결과를 보고 판단한다.

- **고른 테스트가 통과하고 다른 테스트가 깨지지 않았다**: 성공이다. 실패 카운트를 갱신하고 1번으로 돌아간다.
- **이전에 통과하던 다른 테스트가 깨졌다**: 방금 변경을 **되돌린다.** 되돌리는 범위는 이번 단계에서 바꾼 부분뿐이다. 사용자의 다른 미커밋 변경을 건드리는 `git checkout .`, `git reset --hard` 같은 명령은 쓰지 않는다. 되돌린 뒤 다른 방식으로 다시 시도한다.
- **고른 테스트가 아직 실패한다**: 같은 테스트의 실패 횟수를 센다.

### 4. 같은 테스트가 5번 실패하면 멈춘다

같은 테스트에 대해 구현을 5번 시도하고도 통과하지 못하면 **더 시도하지 않고 멈춰서 보고한다.** 보고에는 아래를 담는다.

- 어떤 테스트인지
- 시도한 방법 5가지와 각각의 실패 이유
- 의심되는 원인(테스트가 잘못됐는지, 설계 문제인지)

되돌리기로 끝난 시도도 횟수에 포함한다. 멈출 때는 마지막 시도를 되돌려 코드가 깨진 상태로 남지 않게 한다.

### 5. 0이 될 때까지 반복

실패 카운트가 0이 될 때까지 1~4를 반복한다. 반복하는 동안 한 단계가 끝날 때마다 한 줄로 진행 상황을 알린다(예: `통과: <테스트 이름> — 남은 실패: 3`).

## 보고

가장 마지막 줄에 다음 형식으로 출력한다.

```
남은 실패: N
```

- `N`은 마지막 `npx vitest run` 결과의 실패 수이며, 추측하지 않는다.
- 5회 실패로 멈춘 경우에도 같은 형식을 쓰고, 그 위에 멈춘 이유를 적는다.

요약 줄 앞에는 바꾼 파일 목록을 짧게 적는다. 커밋은 사용자가 요청할 때만 한다.
